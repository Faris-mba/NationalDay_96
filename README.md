# تحدي العائلة 🇸🇦

لعبة جماعية لليوم الوطني السعودي: **تُعرض على التلفزيون**، ويشارك الجميع من **جوالاتهم** عبر مسح رمز QR.
واجهة عربية كاملة (RTL)، ألوان الهوية الوطنية، وسبع جولات تستغرق **32 دقيقة تقريبًا**.

## الشاشات

| المسار | الجهاز | الوظيفة |
|---|---|---|
| `/host` | التلفزيون / اللابتوب الموصول به | ينشئ غرفة برمز من 4 أحرف، يعرض QR ورابط الانضمام، قائمة اللاعبين حيّة، ولوحة تحكم المقدّم |
| `/host/settings` | جوال المقدّم أو اللابتوب | أسماء العائلة، أسئلة العائلة، تعديل بنك الأسئلة، وقائمة المعلومات التي تحتاج مراجعة |
| `/join/[code]` | جوال اللاعب | الاسم + الفئة (صغير/كبير) + الفريق (أو توزيع تلقائي متوازن) |
| `/play/[code]` | جوال اللاعب | أزرار الإجابة A/B/C/D الكبيرة، البازر، والتصويت |

> نصوص شاشة التلفزيون كبيرة عمدًا لتُقرأ من مسافة 4 أمتار.
> لوحة التحكم شريط سفلي يمكن إخفاؤه بزر **«إخفاء ⌄»** حتى لا يزاحم الشاشة.

## إعداد Supabase

1. أنشئ مشروعًا جديدًا على [supabase.com](https://supabase.com) (الخطة المجانية تكفي تمامًا).
2. افتح **SQL Editor → New query**، وألصق محتوى ملف [`supabase/schema.sql`](supabase/schema.sql) كاملًا ثم **Run**.
   ينشئ هذا: الجداول، الفهارس، دالة `server_now()`، تفعيل Realtime، وسياسات RLS.
3. افتح **Project Settings → API** وانسخ:
   - `Project URL` → `NEXT_PUBLIC_SUPABASE_URL`
   - `anon public` key → `NEXT_PUBLIC_SUPABASE_ANON_KEY`

   > 🔑 المشاريع الحديثة تسمّي هذا المفتاح **publishable key** (يبدأ بـ `sb_publishable_`)
   > بدل **anon public**. هو المفتاح نفسه، واللعبة تقبل الاسمين:
   > `NEXT_PUBLIC_SUPABASE_ANON_KEY` أو `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`.
4. تأكّد من **Database → Replication** أن الجداول الخمسة ضمن `supabase_realtime`
   (سكربت الإعداد يضيفها، وهذه مجرد نظرة تأكيد).

### ملاحظة أمنية
اللعبة بلا تسجيل دخول: كل الأجهزة تستخدم مفتاح `anon`، وسياسات RLS تسمح بالقراءة والكتابة للجميع.
هذا مقصود ومناسب لجلسة عائلية مؤقتة — **لا تضع في هذه الجداول أي بيانات حسّاسة**،
واحذف المشروع أو شغّل `select cleanup_old_rooms();` بعد المناسبة.

## التشغيل محليًا

```bash
npm install
cp .env.example .env.local     # ثم املأ القيم من الخطوة 3 أعلاه
npm run dev
```

ثم افتح <http://localhost:3000>.

### للتجربة من جوالك على نفس الشبكة
شغّل `npm run dev -- -H 0.0.0.0`، واضبط في `.env.local`:

```
NEXT_PUBLIC_SITE_URL=http://192.168.x.x:3000
```

(ضع عنوان جهازك على الشبكة) حتى يشير رمز QR لعنوان يصله الجوال.

### الأوامر

| الأمر | الوظيفة |
|---|---|
| `npm run dev` | خادم التطوير |
| `npm run build` | بناء الإنتاج |
| `npm test` | اختبارات منطق اللعبة (18 اختبارًا، بلا شبكة) |
| `npm run typecheck` | فحص الأنواع |
| `npm run lint` | ESLint |

## النشر على Vercel

1. ارفع المستودع إلى GitHub.
2. على [vercel.com](https://vercel.com): **Add New → Project** واختر المستودع.
   يكتشف Vercel إعدادات Next.js تلقائيًا — لا تحتاج تغيير شيء.
3. في **Settings → Environment Variables** أضف (لبيئات Production و Preview و Development):

   | المتغيّر | القيمة |
   |---|---|
   | `NEXT_PUBLIC_SUPABASE_URL` | رابط مشروع Supabase |
   | `NEXT_PUBLIC_SUPABASE_ANON_KEY` | مفتاح `anon public` |
   | `NEXT_PUBLIC_SITE_URL` | *(اختياري)* نطاقك، مثل `https://tahadi.vercel.app` |

4. اضغط **Deploy**.

> `NEXT_PUBLIC_SITE_URL` اختياري: بدونه يشتق رمز QR الرابط من عنوان المتصفّح الحالي.
> اضبطه فقط إن أردت تثبيت نطاق معيّن في الرمز.
> ⚠️ متغيّرات `NEXT_PUBLIC_*` تُحقن وقت البناء — بعد تغييرها **أعد النشر (Redeploy)**،
> وإلا بقي الموقع يعمل بالقيم القديمة.

### ظهرت لك شاشة «ينقص ربط قاعدة البيانات»؟
هذا يعني أن المتغيّرات لم تكن موجودة **وقت بناء** النسخة المنشورة. الأسباب الثلاثة الشائعة:
1. لم تُضف المتغيّرات في Vercel أصلًا.
2. أُضيفت لكن بلا **Redeploy** بعدها.
3. اسم مفتاح مختلف: أخذته من لوحة Supabase الحديثة باسم `PUBLISHABLE_KEY`
   بينما البناء يبحث عن `ANON_KEY` — اللعبة الآن تقبل الاسمين، لكن تأكّد أن اسم
   المتغيّر في Vercel أحدهما بالضبط.

الشاشة نفسها تعرض أي المتغيّرات ناقص تحديدًا.

## يوم الحفلة (خطوات سريعة)

1. **قبل بيوم:** افتح `/host/settings` → أضف **أسماء أفراد العائلة** (اسمان على الأقل، وإلا تُتخطّى جولة التصويت)
   وأسئلة العائلة الخاصة، ثم راجع تبويب **«🔍 معلومات تحتاج مراجعتك»**.
2. ضع صور جولة «خمّن الصورة» في `public/images` حسب [الأسماء المطلوبة](public/images/README.md).
3. **وقت الحفلة:** افتح `/host` على التلفزيون بملء الشاشة (`F11`).
4. الجميع يمسحون رمز QR ← يكتبون أسماءهم ← يختارون صغير/كبير ← الفريق أو توزيع تلقائي.
5. اضغط **▶️ ابدأ اللعبة**.
6. قبل جولة المليون: من تبويب **👥 اللاعبون** اختر **«اجعله بطل الفريق» 🎯** للاعب من كل فريق.

### أزرار المقدّم
**التالي** · **إظهار الإجابة** · **إيقاف مؤقت** · **+10 ثوانٍ** · **تخطّي السؤال / الجولة** ·
**تعديل النقاط يدويًا** (±50/100/500 لكل فريق) · **درجة التقريب** في جولة الصور ·
**✅ صح / ❌ خطأ** لحكم البازر والمليون · **وسائل المساعدة** · **🔊 كتم الصوت**.

|---|---|

| ⚡ أسرع إجابة | 12 |

| 😂 أسئلة العائلة الافتراضية | 8 |

### شكل السؤال

```json
{
  "id": "t01",
  "round": "trivia",
  "text": "متى يوافق اليوم الوطني السعودي من كل عام؟",
  "options": ["23 سبتمبر", "22 فبراير", "1 مايو", "11 نوفمبر"],
  "answer": 0,
  "category": "all",
  "difficulty": "easy",
  "verify": false
}
```

- `round`: `trivia` · `kids` · `dialect` · `image` · `buzzer` · `family` · `million`
- `answer`: **فهرس** الإجابة داخل `options` (يبدأ من صفر)
- `category`: `kids` · `adults` · `all`
- `verify`: `true` يعني أن المعلومة تحتاج تأكيدك قبل الحفلة

### ⚠️ 30 سؤالًا تحتاج مراجعتك
كل سؤال عليه `"verify": true` يحمل معه حقل `verifyNote` يشرح سبب الشك.
**اعرضها كلها مرتّبة في `/host/settings` ← تبويب «🔍 معلومات تحتاج مراجعتك»**،
وعدّلها أو استبعدها من هناك مباشرة.

تقع في ثلاث فئات:
1. **معلومات قد تتغيّر مع الوقت** — إكسبو 2030، مونديال 2034، أكبر مدينة سكانيًا.
2. **أرقام وتواريخ تختلف بين المصادر** — مساحة المملكة، ارتفاع جبل السودة، عدد ألقاب كأس آسيا، سنة أول موقع يونسكو.
3. **نسبة كلمة إلى لهجة منطقة** — أغلب أسئلة «وش الكلمة؟»، لأن كثيرًا من الكلمات مشتركة بين مناطق عدة.

### التعديل بلا لمس الكود
من `/host/settings` ← **📚 بنك الأسئلة** يمكنك: البحث والتصفية حسب الجولة، تعديل أي سؤال
(النص، الخيارات، الإجابة الصحيحة، مسار الصورة)، **استبعاد** سؤال لا يعجبك، أو **إضافة** أسئلة جديدة.
كل ذلك يُحفظ في عمود `settings` للغرفة، والملف الأصلي يبقى كما هو.

## مخطط قاعدة البيانات

```
rooms ────┬──< players ──┬──< answers
          │              ├──< buzzes
          │              └──< votes
```

### `rooms` — المصدر الوحيد لحالة اللعبة
| العمود | الغرض |
|---|---|
| `code` | رمز الانضمام (4 أحرف، بلا I و O تفاديًا للّبس) |
| `phase` | `lobby` · `question` · `reveal` · `finished` |
| `round_index` / `step_index` | موضع اللعبة في قائمة التشغيل |
| `current_question` | **نسخة كاملة** من السؤال المعروض (jsonb) |
| `question_started_at` / `question_duration` | مرجع العدّ التنازلي بساعة الخادم |
| `paused_at` / `paused_ms` | الإيقاف المؤقت ومجموع مدّته |
| `score_falcons` / `score_elite` | لوحة النقاط |
| `settings` | أسماء العائلة، الأسئلة المخصّصة، الاستبعادات |
| `round_state` | حالة الجولة: درجة التقريب، البازر، وسائل المساعدة، سلّم المليون |

> **لماذا نسخة السؤال داخل الصف؟** لأن الجوالات والتلفزيون لا تحتاج حينها أي منطق مشترك
> لاختيار السؤال: كلها تقرأ `current_question` وتعرضه. هذا يلغي احتمال اختلاف
> الأجهزة حول السؤال المعروض، ويجعل إعادة التحميل بعد انقطاع فورية.

### `players`
`(room_id, client_id)` فريدة — و`client_id` محفوظ في `localStorage`،
فإعادة فتح الصفحة تُرجع اللاعب لنفس الفريق ونفس النقاط.

### `buzzes`
`created_at timestamptz default now()` — يملؤه **Postgres**، ولا يرسله العميل إطلاقًا.
الترتيب `order by created_at` فوقت الخادم هو الحَكَم، لا ساعة الجوال.

### `answers` / `votes`
`(room_id, player_id, question_id)` فريدة ⇒ `upsert`، فيمكن للاعب تغيير إجابته
ما دام الوقت باقيًا، بلا تكرار صفوف ولا احتساب مزدوج.

## تدفّق الأحداث في Realtime

ثلاث طبقات، لكل منها دور واضح:

```
                    ┌──────────────────────────────┐
                    │  Postgres: جدول rooms        │  ← المصدر الموثوق الوحيد
                    └──────────────┬───────────────┘
                                   │ postgres_changes
        ┌──────────────────────────┼──────────────────────────┐
        ▼                          ▼                          ▼
  📺 /host                   📱 /play                   📱 /play
```

| الطبقة | الاستخدام | لماذا |
|---|---|---|
| **postgres_changes** | `rooms` (حالة اللعبة) و`players` (النقاط والفرق) و`answers`/`buzzes`/`votes` | الحدث يصل **بعد** ثبوت التغيير في القاعدة، فما تراه الشاشة مطابق لما هو مخزَّن |
| **Presence** | من المتصل **الآن** فعليًا على قناة `room:{CODE}` | تمييز من أغلق جواله عمّن ما زال في اللعبة، بلا كتابة في القاعدة |
| **Broadcast** | أحداث لحظية لا تحتاج حفظًا | مؤثرات فورية بلا رحلة ذهاب وإياب للقاعدة |

### مثال: دورة سؤال كاملة
```
المقدّم يضغط «التالي»
   └─> UPDATE rooms SET phase='question', current_question={…}, question_started_at=now()
          └─> postgres_changes ─> التلفزيون يعرض السؤال + كل الجوالات تعرض الخيارات

اللاعب يضغط خيارًا
   └─> UPSERT answers  ──> postgres_changes ─> عدّاد «جاوبوا n/m» على التلفزيون

المقدّم يضغط «إظهار الإجابة»
   └─> يقرأ المقدّم كل الإجابات، يصحّحها، ويكتب النقاط مرة واحدة
          └─> UPDATE rooms (phase='reveal' + النقاط) + UPDATE players
                 └─> postgres_changes ─> إبراز الإجابة الصحيحة وأنيميشن لوحة النقاط
```

**الاحتساب يجري في شاشة المقدّم فقط** — كاتب واحد يعني استحالة احتساب النقاط مرتين.
ولو ضُغط «إظهار الإجابة» مرتين، الإجابات المصحَّحة سابقًا (`is_correct` ليست `null`) تُتجاهل.

## الاعتمادية

اللعبة فعالية حيّة: الفشل أمام العائلة كلها غير مقبول. لذلك:

| الخطر | المعالجة |
|---|---|
| انقطاع إنترنت التلفزيون | كل شيء في صف `rooms`. عند عودة الاتصال (`SUBSCRIBED`) تُعاد قراءة الحالة كاملة فورًا |
| إعادة تحميل صفحة التلفزيون | رمز الغرفة محفوظ في `localStorage`؛ الصفحة تستأنف من نفس السؤال والنقاط |
| اللاعب أغلق المتصفّح | `client_id` في `localStorage` يرجعه لنفس السجل: نفس الفريق ونفس النقاط |
| **ساعة جوال خاطئة** | العدّ التنازلي وترتيب البازر يُحسبان بساعة الخادم: `server_now()` تعاير فرق الساعة عند كل اتصال، و`created_at` في البازر من Postgres |
| تبويب في الخلفية | `visibilitychange` + `online` + `focus` تُطلق مزامنة كاملة عند العودة |
| حدث Realtime ضائع | مزامنة احتياطية هادئة كل 20 ثانية |
| ضغطتان متزامنتان | قيود `unique` + `upsert` تمنع التكرار؛ وتعارض رمز الغرفة يعيد التوليد حتى 8 مرات |
| سؤال خاطئ أو محرج | **تخطّي السؤال** و**تخطّي الجولة** و**⏮ السابق** متاحة في أي لحظة |
| نتيجة غير عادلة | **تعديل النقاط يدويًا** ±50/100/500 لكل فريق في أي وقت |
| الصوت يزعج | زر كتم على التلفزيون وعلى كل جوال (يُحفظ التفضيل محليًا) |
| الصور غير جاهزة | صورة مؤقتة تلقائية مكتوب عليها اسم الإجابة حتى تضيف صورك |

**الأصوات** بـ Web Audio بلا أي ملفات: عدّ تنازلي، إجابة صحيحة، بازر، وبداية سؤال.
تبدأ بعد أول لمسة من المستخدم (سياسة المتصفحات) — أول لمسة على `/host` أو زر الانضمام تكفي.

**الختام:** كونفيتي أخضر وأبيض وذهبي + إعلان الفريق الفائز وأفضل اللاعبين.
ويحترم إعداد `prefers-reduced-motion` لمن يزعجه الأنيميشن.
